가계부 앱 사용자 인터뷰 — 주요 내용·개선 방향

초기 사용자 1:1 인터뷰 4건(A~D) 발췌본 기반 · 제품팀 작업 문서 · 인용은 원문(영어) 그대로

이번 인터뷰에서 확인된 결론

  • "자동으로 안 되면 안 쓴다"가 강한 공통 신호. A는 수동 입력을 아예 안 하고, 거래 확인을 계속 요구하던 다른 앱은 그대로 이탈. C는 앱 자체를 "homework"로 느낌. 입력·확인 부담을 줄이는 것이 리텐션의 핵심이라는 가설.
  • 자동 분류 정확도가 신뢰를 직접 깎는다. B는 월세가 'shopping'으로 잘못 분류된 뒤 "stopped trusting the numbers". 분류 오류는 단순 불편이 아니라 숫자 전체에 대한 신뢰 문제로 번짐.
  • 분류·카테고리를 사용자가 고칠 수 있어야 한다. B는 "merchant 규칙", D는 "kid stuff" 같은 자기네 카테고리를 원함. 현재 카테고리 모델이 사용자의 머릿속 분류와 안 맞음.
  • 톤이 사용자를 밀어낸다. C는 전체 지출을 한눈에 보고 "freaked out", 빨간 'over budget' 경고엔 "great, thanks, I know"로 반응. 정보는 맞아도 전달 방식이 불안·압박감을 키움.
  • 제품 결정이 필요한 항목 2개: ① 공동(파트너) 사용 지원 여부 — D에게는 단일 사용자 구조가 "dealbreaker". ② "이번 달 괜찮아?"에 답하는 단순 요약을 핵심 화면으로 둘지(A가 명시적으로 요구).

우선 정리된 주제 (개선 방향)

정렬 기준: 언급한 사람 수 × 행동 영향(이탈·미사용으로 이어졌는지) × 근거의 직접성. 표본이 4명 발췌본이라 모든 수치는 방향성으로만 봐주세요.

  • 1
    입력·확인 부담이 곧 이탈로 이어짐 (자동화가 기본값이어야 함)
    근거: A, C (2명) · 다른 앱 이탈·앱 미사용 등 실제 행동으로 연결 근거 수준: 중
  • 2
    자동 분류 오류가 숫자 전체에 대한 신뢰를 떨어뜨림
    근거: B, D (2명) · B는 "stopped trusting the numbers"까지 진행 근거 수준: 중
  • 3
    카테고리를 사용자가 직접 정의·수정하고 싶어 함 (merchant 규칙, 커스텀 카테고리)
    근거: B, D (2명) · 둘 다 구체적 요청으로 표현 근거 수준: 중
  • 4
    경고·요약 톤이 불안과 압박감을 키움
    근거: C(강), A(요약 니즈로 연결) · 1~2명 사례라 방향은 분명하나 추가 확인 필요 근거 수준: 약~중
  • 5
    공동(파트너) 사용 지원 — D에게는 도입 자체를 막는 요인
    근거: D (1명) · 단일 사례지만 "dealbreaker"로 강하게 표현 근거 수준: 약(1명)

개선안 백로그

바로 트래커로 옮길 수 있게 정리했습니다. "기대 효과"는 인터뷰에서 측정된 값이 아니라 가설입니다. 담당자·일정·수치는 데이터에 없어 넣지 않았습니다.

우선순위주제/문제근거제안 개선 방향기대 효과(가설)확인 방법
1 매번 수동으로 입력·확인해야 해서 앱을 안 열게 됨 A: 자동 아니면 안 씀, 거래 확인 요구하던 앱 이탈 / C: "feels like homework" 자동 분류를 기본값으로, 거래 확인은 선택/일괄로. 첫 화면에서 입력을 요구하지 않기 초기 이탈·미사용 감소 온보딩 직후 N일 리텐션, 확인 프롬프트 노출 전후 비교
2 자동 분류가 자주 틀려 숫자를 못 믿게 됨 B: 월세→'shopping' 오분류, 3번째부터 신뢰 상실 / D: 오류 있으나 체념적 수용 분류 정확도 개선 + 쉬운 수정 UX + "이 가맹점은 항상 ○○" 규칙 저장 숫자 신뢰 회복, 수정 반복 감소 분류 수정 빈도, 규칙 사용률, 신뢰 관련 후속 인터뷰
3 앱 카테고리가 사용자의 분류 방식과 안 맞음 B: merchant 규칙 원함 / D: "kid stuff"(보육+의류+학교비용) 묶음 불가 커스텀 카테고리 생성 + 여러 항목 묶기 + 가맹점→카테고리 규칙 분류 만족도·자기화 정도 향상 커스텀 카테고리 생성률, 규칙 설정률
4 직설적 경고('over budget' 빨간 표시)와 전체 노출이 불안을 줌 C: 전체 보고 "freaked out", 빨간 경고에 "thanks, I know" / A: "그냥 괜찮은지만 말해줘" 톤 완화, 단계적 정보 공개, "이번 달 괜찮아?"형 한 줄 상태를 우선 노출 복귀율·체류 개선, 회피 감소 경고 카피 A/B, 단순 요약 화면 도입 전후 복귀율
5 혼자만 쓰는 구조라 파트너와 공유가 안 됨 D: "single-user thing is a dealbreaker", 둘 다 봐야 함 공동 계정/공유 보기 지원 여부를 제품 결정으로 검토 커플·가족 세그먼트 도입 가능성 공유 니즈 규모를 추가 인터뷰/서베이로 정량화

주제별 상세 카드

1. 입력·확인 부담이 곧 이탈로 이어짐 근거 수준: 중

문제매 거래를 직접 기록하거나 확인해 줘야 하면, 사람들은 그냥 앱을 안 연다. 자동화가 안 되면 "안 쓰겠다"는 입장이 명확하다.
근거 A: "I check my balance like five times a day but I never actually log anything. Categorizing every coffee is just... no. If it doesn't do it for me automatically I'm not going to do it." A: "I tried [other app] and it kept asking me to confirm transactions and I just stopped opening it." C: "It's not that it's hard, it's that it feels like homework. And a bit stressful."
영향입력·확인 마찰이 초기 이탈·미사용의 직접 원인일 가능성(가설). A는 잔액은 하루 5번 보면서도 기록은 안 함 — 보는 동기는 있으나 입력 동기는 없음.
제안자동 분류를 기본값으로 두고, 거래 확인은 선택 또는 일괄 처리. 온보딩·첫 화면에서 사용자에게 입력을 요구하지 않기.
확인 방법확인 프롬프트 노출 여부에 따른 초기 리텐션 비교, "기록 없이도 가치를 느끼는지" 후속 인터뷰.

2. 자동 분류 오류가 숫자 신뢰를 떨어뜨림 근거 수준: 중

문제자동 분류가 틀리는 것 자체보다, 반복되면 "숫자를 못 믿겠다"로 번지는 게 문제다.
근거 B: "The auto-categorization is wrong a lot though — it put my rent under 'shopping' and I had to fix it. After the third time I kind of stopped trusting the numbers." D: "Auto-categorization being off was annoying but I expected it, every app does that."
영향분류 오류는 단일 항목 불편이 아니라, 앱이 보여주는 합계·대시보드 전체에 대한 신뢰를 깎음(B). D처럼 "원래 다 그렇지"하고 체념하는 사용자도 있어 기대치 자체가 낮아져 있음.
제안분류 정확도 개선과 함께 쉬운 수정 UX, "이 가맹점은 항상 ○○" 규칙 저장으로 반복 오류를 사용자가 끊을 수 있게.
확인 방법분류 수정 빈도, 규칙 사용률, 신뢰 관련 후속 질문.

3. 카테고리를 사용자가 직접 정의·수정하고 싶어 함 근거 수준: 중

문제앱이 정해둔 카테고리가 사용자의 실제 분류 방식과 안 맞고, 직접 만들거나 규칙화할 방법이 없다.
근거 B: "I'd love a way to set rules, like 'this merchant is always groceries'." D: "The categories don't match how we think — we have 'kid stuff' which is daycare plus clothes plus random school fees, and there's no way to make that."
영향2번(분류 신뢰) 문제와 맞닿아 있음 — 규칙·커스텀 카테고리는 오분류를 사용자가 직접 해결하는 수단이기도 함.
제안커스텀 카테고리 생성, 여러 종류 지출을 한 카테고리로 묶기, 가맹점→카테고리 규칙 저장.
확인 방법커스텀 카테고리·규칙 생성률, 생성 후 분류 수정 빈도 변화.

4. 경고·정보 노출의 톤이 불안과 압박을 키움 근거 수준: 약~중

문제정보는 정확해도 전달 방식(전체 한꺼번에 노출, 빨간 'over budget' 경고)이 사용자를 불안하게 하고 앱에서 멀어지게 한다.
근거 C: "Honestly I downloaded it, connected my bank, then got a little freaked out seeing everything in one place and didn't go back for like two weeks." C: "When I did come back the dashboard had this big red 'over budget' thing and I was like, great, thanks, I know." A: "What I actually want to know is — am I okay this month or not? Just tell me that."
영향C는 톤 때문에 2주간 앱을 회피(실제 미사용 행동). A의 "그냥 괜찮은지만 알려줘"는 같은 니즈의 다른 표현 — 판단보다 안심 가능한 요약을 원함. 다만 강한 사례는 C 1명이라 추가 확인 필요.
제안경고 카피 완화, 정보의 단계적 공개(한 번에 다 보여주지 않기), "이번 달 괜찮아?"형 한 줄 상태를 우선 노출.
확인 방법경고 카피 A/B, 단순 요약 화면 도입 전후 복귀율·체류.

5. 공동(파트너) 사용 필요 — 도입 자체를 막는 요인 근거 수준: 약(1명)

문제재정을 파트너와 함께 관리하는 사용자는 단일 사용자 구조 때문에 앱을 못 쓴다.
근거 D: "I share finances with my partner so the single-user thing is a dealbreaker honestly. We both need to see it."
영향1명 사례지만 "dealbreaker"로 강하게 표현 — 해당 세그먼트(커플·가족 공동 관리)에는 진입 장벽일 수 있음. 규모는 미확인.
제안공동 계정/공유 보기 지원 여부를 제품 결정 안건으로 다루기.
확인 방법공유 니즈 규모를 추가 인터뷰·서베이로 정량화한 뒤 우선순위 판단.

발췌 4건에서 두 갈래의 태도가 보입니다. 단정하기엔 표본이 작으니 가설로만 봐주세요.

추가 확인 필요사항

  • 표본·정량 근거 부재. 4명 발췌라 비율·리텐션 같은 수치는 없습니다. 각 주제(특히 자동화 부담, 톤으로 인한 회피)의 규모를 서베이/행동 로그로 정량화해야 우선순위를 확정할 수 있습니다.
  • 공동 사용 니즈 규모. D 1명에서 "dealbreaker"로 나왔습니다. 커플·가족 공동 관리 세그먼트가 얼마나 큰지 추가 확인 필요.
  • "단순 요약"의 구체 형태. A는 "이번 달 괜찮은지만 알려줘"라고 했지만, 무엇을 보여줘야 "괜찮다/아니다"로 받아들이는지는 미확인. 컨셉 테스트 권장.
  • 톤 vs 정보의 균형. C는 경고를 싫어했지만, 경고를 없애는 게 맞는지(필요한 알림을 놓치게 될 위험)는 발췌만으로 판단 불가. 카피/노출 방식 A/B로 확인.
  • 능동 관리형의 비중. B 같은 "주간 점검형"이 얼마나 되는지에 따라 자동화 기본값과 수동 통제권의 균형점이 달라집니다.
