체크아웃 리디자인 사용성 테스트

모더레이티드 원격 테스트 · 참가자 5명(P1–P5) · 과제 4개(T1–T4) · 클릭형 프로토타입(v3)

발표용 요약 — 원자료: usability_test_notes.md

이번 테스트에서 확인된 결론

  • 마찰은 결제 단계에 몰려 있음 장바구니 담기(T1)는 5명 전원 문제없이 성공
  • 할인 코드 입력란 위치가 가장 반복적으로 걸림 5명 모두 직간접적으로 언급·헤맴, P3은 미적용 결제(실패)
  • 결제 진입 후 배송지 변경 경로가 안 보임 P1 실패(SEQ 2/7), P2 우회, P5 머뭇거림
  • 결정 필요: 할인 코드 입력란을 장바구니로 노출할지부터 정해야 함

우선 개선 이슈

1할인 코드 입력란을 찾기 어려움

제안 장바구니 화면에 프로모 코드 입력란 노출, 결제 화면에도 위치 또렷이

근거 수준 강 — 5명 모두에게서 반복 확인, 모더레이터도 지목

  • P3 끝까지 못 찾고 미적용 결제, 본인은 인지 못 함(SEQ 3/7)
  • P1 장바구니에서 찾다 결제 화면에서 뒤늦게 발견

외 3명(P2·P4·P5) 추가 언급/우회 — 전체 근거는 작업 문서 참고

우선 개선 이슈

2결제 중 배송지 변경 경로가 안 보임

제안 결제 화면 내 배송지 영역에 "변경/편집" 진입점을 눈에 띄게 배치

근거 수준 중 — 실패 1명 + 우회·머뭇거림 2명, 모더레이터 노트로 보강

  • P1 끝내 못 찾고 포기(실패) — "I'd just call support at this point honestly"
  • P2 장바구니로 되돌아가 우회, 시간 소요

외 1명(P5) 머뭇거림 — 전체 근거는 작업 문서 참고

우선 개선 이슈

3결제 버튼이 비활성처럼 보여 "고장"으로 오해

제안 버튼 활성/비활성 상태를 명확히 구분, 미입력 필수 항목 안내 노출

근거 수준 약(1명) — 단일 사례지만 결제 완료를 막는 차단성 이슈, 모더레이터도 어포던스 문제로 지목

  • P4 "Nothing's happening when I click." — 필수 항목 미입력을 인지 못 하고 폼이 깨진 줄 알고 실패

추가 확인 필요사항

  • 완료율 외 핵심 지표(과제 소요 시간, 미스클릭 수)는 이번 메모에 수집되지 않음
  • SEQ는 5명 전원·전 과제가 아니라 2건(T4-P1, T2-P3)만 기록됨
  • 매출·전환 영향은 측정되지 않음 — "기대 효과"는 모두 가설
