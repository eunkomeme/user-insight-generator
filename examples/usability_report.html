이번 테스트에서 확인된 결론

  • 장바구니 담기(T1)는 5명 전원 문제없음. 마찰은 결제 단계에 몰려 있음.
  • 할인 코드 입력란 위치가 가장 큰 문제. 5명 중 4명이 헤매거나 실패했고, P3은 코드를 못 넣은 채 결제까지 진행함(미적용 결제).
  • 결제 중 배송지 변경 경로가 막혀 있음. P1은 방법을 못 찾고 포기(I'd just call support).
  • 결제 버튼이 눌러도 되는 상태처럼 보이지 않아 P4가 "고장난 줄" 알고 과제 실패.
  • 결정 필요 할인 코드 입력란을 장바구니 화면으로 옮길지 먼저 정해야 함(가장 빠른 개선).

이슈별 상세 카드

이슈 1. 할인 코드 입력란을 결제 화면에서 찾기 어려움 근거 강

문제사용자가 할인 코드를 장바구니에서 넣으려 하는데, 입력란이 결제(payment) 화면에 있어 잘 못 찾음.
근거P1: 장바구니에서 먼저 찾다가 결제 화면에서 발견(where do I put the code... oh it's down here) · P3: 끝까지 못 찾고 코드 없이 결제, 본인은 모름(SEQ 2 = 3/7) · P4: 스크롤 후 결제 화면에서 발견 · P2: I almost missed it · P5: the promo code placement is weird
영향코드를 못 넣은 채 결제가 끝나면(P3 사례) 사용자 불만·문의로 이어지고, 프로모션 효과도 떨어질 수 있음(가설).
제안장바구니 화면에 프로모 코드 입력란을 노출. 결제 화면에도 유지하되 위치를 또렷하게.
확인 방법수정안에서 T2를 다시 수행하게 하고, 직접(헤매지 않고) 적용한 비율을 비교.

이슈 2. 결제 화면에서 배송지 변경 버튼을 찾기 어려움 근거 중

문제결제 단계에 들어간 뒤 배송지를 바꾸려는데 변경 경로가 안 보여서, 포기하거나 장바구니로 되돌아가는 우회를 함.
근거P1: 방법 못 찾고 포기(I'd just call support at this point honestly, SEQ 2/7) · P2: 장바구니로 돌아갔다 다시 결제 진입 · P5: took me a sec to see the edit link, it's pretty small · 모더레이터 메모: 결제 진입 후 명확한 진입점 없음
영향배송지 오류를 뒤늦게 발견한 사용자가 결제를 멈추거나 고객센터로 빠질 수 있음(가설).
제안결제 화면 배송지 영역에 "변경" 버튼을 링크가 아닌 버튼형 CTA로, 배송지 카드 우측 상단에 고정 배치.
확인 방법수정안에서 T4 재수행, 배송지 변경 성공률과 머뭇거림 여부 비교.

이슈 3. 결제 버튼이 눌러도 되는 버튼처럼 보이지 않음 근거 약 · 1명

문제결제 버튼이 회색(비활성)처럼 보여, 필수 입력칸이 비어 있다는 걸 모른 채 "버튼이 고장났다"고 인식.
근거P4: 과제 실패 — Nothing's happening when I click (필수 필드가 빈 줄 몰랐음)
영향차단성이 큰 문제(결제 자체가 막힘). 다만 1명 사례라 재현 확인 필요.
제안활성/비활성 버튼 상태를 또렷이 구분하고, 빈 필수칸을 인라인으로 안내(무엇을 채워야 하는지 표시).
확인 방법수정안에서 T3 재수행, 같은 혼동이 또 나오는지 확인.

이슈 4. CVV 입력 안내가 부족함 근거 약 · 비차단

문제CVV가 어디 적힌 숫자인지 몰라 잠깐 멈춤(과제는 성공).
근거P2: Is this the 3 digits on the back?
영향막히는 수준은 아니지만 작은 헷갈림이 쌓이면 입력 속도에 영향(가설).
제안CVV 칸 옆에 위치 안내(카드 뒷면 3자리) 툴팁/도움말 추가.
확인 방법수정안에서 CVV 입력까지 걸리는 시간/머뭇거림 비교.

추가 확인 필요사항

  • 완료율·과제 소요 시간 등은 이번 메모에 수집되지 않음 — 다음 테스트에서 계측 권장.
  • 이슈 3(결제 버튼)·CVV는 각각 1명 사례 — 추가 참가자로 재현 여부 확인 필요.
  • SEQ는 2건(P1-T4, P3-T2)만 기록됨 — 전 과제 SEQ 수집 시 비교가 쉬워짐.
  • 매출·전환 영향은 자료에 없음 — 개선 후 결제 전환 지표와 연결해 검증 권장.
