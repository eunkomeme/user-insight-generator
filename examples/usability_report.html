체크아웃 리디자인 사용성 테스트 — 작업 문서

모더레이티드 원격 테스트 · 참가자 5명(P1–P5) · 1인당 약 30분 · 클릭형 프로토타입(v3) · 과제 4개(T1–T4)

이번 테스트에서 확인된 결론

  • 마찰은 결제 단계에 몰려 있음 — 장바구니 담기(T1)는 5명 전원 문제없이 성공.
  • 할인 코드 입력란 위치가 가장 큰 문제. 5명 중 4명이 헤매거나 실패했고, P3은 코드를 못 찾아 미적용 상태로 결제(본인은 인지 못 함). 모더레이터도 반복 발생으로 지목.
  • 결제 중 배송지 변경(T4)은 진입 경로가 불명확. P1은 끝내 못 찾고 포기(SEQ 2/7), P2는 장바구니로 되돌아가 우회, P5는 편집 링크가 작아 머뭇거림.
  • 저장 카드 결제(T3)에서 P4가 비활성처럼 보이는 결제 버튼 때문에 "고장 났다"고 판단하고 실패 — 1명 사례지만 결제 완료를 막는 차단성 이슈.
  • 결정 필요: 할인 코드 입력란을 장바구니 화면으로 노출할지부터 정해야 함(가장 빠르고 영향 큰 개선).

이슈별 상세 카드

1할인 코드 입력란을 결제 화면에서 찾기 어려움근거 강

문제다수가 코드를 장바구니에서 넣으려 했지만 입력란이 결제(payment) 화면에 있어 잘 못 찾음. 한 명은 끝까지 못 찾고 미적용 상태로 결제.
근거
  • P3 T2 — 실패. 끝까지 못 찾고 코드 없이 결제, 본인은 미적용 사실 인지 못 함. SEQ 3/7. "I assumed there'd be a promo box right in the cart."
  • P1 T2 — 성공했으나 장바구니에서 먼저 찾다 결제 화면에서 뒤늦게 발견. "Wait, where do I put the code... oh it's down here."
  • P4 T2 — 성공했으나 결제 화면에서 스크롤한 뒤에야 입력란 발견.
  • P2 T2 — 직접 성공했지만 따로 언급. "The code thing tripped me up too, I almost missed it."
  • P5 T2 — 직접 성공했지만 전체 코멘트에서 지적. "the promo code placement is weird."
영향코드 미적용 결제는 고객 불만·문의로 이어지고 프로모션 효과도 떨어질 수 있음(가설, 이번 테스트에서 매출 영향은 측정 안 됨).
제안장바구니 화면에 프로모 코드 입력란을 노출. 결제 화면에도 유지하되 위치를 또렷하게.
확인 방법수정안에서 T2 재수행 — 헤매지 않고 직접 적용한 비율, 미적용 결제 발생 여부 비교.

2결제 진입 후 배송지를 바꾸는 경로가 안 보임근거 중

문제결제 단계에 들어선 뒤 배송지를 변경할 진입점이 뚜렷하지 않음. 한 명은 끝내 못 찾고 포기, 다른 사람은 장바구니로 되돌아가 우회.
근거
  • P1 T4 — 실패. 결제 도달 후 배송지 변경 방법을 못 찾고 포기. SEQ 2/7. "I'd just call support at this point honestly."
  • P2 T4 — 성공했으나 장바구니로 되돌아가 플로우를 다시 타는 우회, 시간 소요.
  • P5 T4 — 성공했으나 머뭇거림. "took me a sec to see the edit link, it's pretty small."
영향변경 경로를 못 찾으면 결제 중 이탈이나 지원 문의로 이어질 수 있음(가설). P1은 실제로 "지원에 전화하겠다"며 포기.
제안결제 화면 내 배송지 영역에 "변경/편집" 진입점을 눈에 띄게(링크 크기·위치 강화) 배치.
확인 방법수정안에서 T4 재수행 — 직접 변경 성공률, 우회·머뭇거림 빈도 비교.

3결제 버튼이 비활성처럼 보여 "고장"으로 오해근거 약(1명)

문제저장 카드로 결제(T3)할 때 결제 버튼이 회색 처리되어 비활성처럼 보임. 눌러도 반응이 없자 폼이 깨진 것으로 오해하고 실패 — 실제로는 필수 항목이 비어 있었음.
근거
  • P4 T3 — 실패. 버튼이 비활성처럼 보여 폼이 고장 난 줄 앎, 필수 항목 미입력은 인지 못 함. "Nothing's happening when I click."
영향1명 사례지만 결제 완료 자체를 막는 차단성 문제. 모더레이터도 시각적 표현(어포던스) 이슈로 지목.
제안버튼의 활성/비활성 상태를 명확히 구분하고, 비활성일 때 어떤 필수 항목이 비었는지 안내를 노출.
확인 방법수정안에서 T3 재수행 — 버튼 상태를 오해하는지, 미입력 안내가 이해되는지 확인.

4CVV 입력 위치를 헷갈려 함근거 약(1명)

문제저장 카드 결제 중 CVV 입력에서 어떤 숫자를 넣어야 하는지 잠시 헷갈림(성공으로는 이어짐).
근거
  • P2 T3 — 성공했으나 CVV 필드에서 머뭇거림. "Is this the 3 digits on the back?"
영향작은 헷갈림 수준이며 1명만 관찰됨 — 우선순위 낮음.
제안CVV 입력란에 "카드 뒷면 3자리" 같은 보조 안내 텍스트 추가.
확인 방법1명 사례 — 다음 테스트에서 재현되는지 확인 후 우선순위 재판단.

모더레이터 메모(원문 요지)

  • 할인 코드 위치(T2)가 반복적으로 언급됨.
  • T4(배송지 변경)는 결제 진입 후 명확한 진입점이 없음.
  • P4의 비활성처럼 보이는 결제 버튼은 시각적 표현(어포던스) 이슈일 수 있음.

수집된 측정값

  • SEQ는 T4-P1(2/7), T2-P3(3/7) 두 건만 기록됨. 그 외 과제·참가자의 SEQ는 미수집.
  • 완료율은 위 과제별 표의 성공/실패 집계가 전부이며(과제별 4/5 또는 5/5), 과제 소요 시간·미스클릭 수는 수치로 기록되지 않음.

이 보고서 보는 법

본문은 바로 실행에 옮기기 위한 문서이고, 이 부록은 근거를 되짚기 위한 영역입니다. 각 이슈의 "근거 수준(강·중·약)"은 몇 명에게서, 얼마나 차단적으로 관찰됐는지를 뜻합니다 — 여러 명에게 반복되면 강, 1명 사례면 약으로 표기했습니다. "성공(우회)/머뭇거림"은 과제는 마쳤지만 개선 신호가 있는 경우입니다. 인용문은 메모 원문 그대로 유지했습니다.

추가 확인 필요사항

  • 완료율 외 핵심 지표(과제 소요 시간, 미스클릭 수)가 이번 메모에 수집되지 않음 — 다음 테스트에서 계측 권장.
  • SEQ가 5명 전원·전 과제가 아니라 2건(T4-P1, T2-P3)만 기록됨 — 과제별 체감 난이도 비교가 어려움, 일관되게 수집 권장.
  • 참가자 5명은 패턴의 방향성만 보여줌 — T2처럼 4명에게 반복된 신호는 신뢰할 만하나, P4 버튼 오해·P2 CVV처럼 1명 사례는 추가 확인 후 우선순위 확정 필요.
  • 매출·전환·이탈에 대한 실제 영향은 측정되지 않음 — 본문의 "기대 효과"는 모두 가설이며, 수정안 재테스트 또는 실데이터로 검증 필요.
