# Maze methodology notes

Methodology distilled from Maze's UX research articles, kept as *guidance to draw on* — not
structures to copy. Use these principles to inform analysis and reporting; don't mechanically
reproduce Maze's formats or product framing. Sources are listed at the end.

## Stakeholder buy-in & reporting (from Maze's stakeholder buy-in article)

The practical lesson for synthesis: a finding that nobody acts on has no value, so report for the
decision, not for completeness.

- **Lead with impact ("so what"), then context, then evidence.** Maze frames this as the Pyramid
  Principle: state the conclusion first, then the supporting insight, then the data. Reports should
  open with what matters and why, not with methodology.
- **Show the data that connects user insight to outcomes** stakeholders track (retention, risk,
  effort, conversion) — but only data you actually have. *In this skill, that connection is a
  hypothesis to label, never an invented number.*
- **Make insights actionable.** Maze's reframing of "users found this confusing" into "simplifying
  this step could reduce drop-off" is a useful tone — but treat the quantified version as a
  hypothesis unless the data measured it.
- **Show, don't just tell.** Visual evidence (clips, heatmaps, quotes, before/after) makes findings
  tangible. Our analog: the quote wall, evidence tables, and visible evidence-to-claim chains.
- **Match format to audience.** Live walkthrough for alignment; a shareable written report for async
  reference. Our self-contained HTML report serves the async, revisitable case.

## Affinity diagrams (from Maze's affinity diagrams article)

Directly informs the thematic/affinity analysis pattern. The method (also called the KJ method):

1. **Collect** each raw observation as its own note (one quote/idea per note).
2. **Transfer** everything to a shared space so patterns can be seen together.
3. **Cluster** related notes; group by similarity *before* naming.
4. **Name clusters** from what's in them — themes emerge bottom-up, not from pre-set buckets.
5. **Reinforce** clusters with supporting context (quotes, examples).
6. **Link clusters** and step back to find higher-order patterns and a problem statement.

Key takeaways for us: let themes emerge from the data rather than imposing categories; stack
repeated points to show weight of evidence; affinity mapping is a *bridge* from raw research to
design direction, not the whole analysis. Don't force-fit observations into a tidy cluster they
don't belong to.

## Usability metrics (from Maze's "12 key usability metrics" article)

Use when raw metric data exists. Four families:

- **Completion / success:** completion (task success) rate, direct vs. indirect success, fail rate.
  Completion rate = (completed tasks / assigned tasks) × 100. *Direct* success = user took the
  expected path; *indirect* = succeeded via a different path.
- **Duration:** time on task, time on screen. Interpret only in context — slow can mean confusion or
  just reading; pair with errors/misclicks.
- **Errors:** misclick rate = (misclicks / total clicks) × 100; number of errors. High values point
  to unclear hierarchy or mismatched expectations (cf. Jakob's Law).
- **Satisfaction:** SEQ (single 1–7 ease question per task), SUS (10 items, scored ×2.5 to 0–100;
  ~68 average, >70 good, >85 excellent), SMEQ (perceived mental effort), help requests.

Critical framing principles from the article:
- Metrics measure the **design's effectiveness, not the user**.
- A number tells you *what*; you still need qualitative evidence for *why* — review time-on-task
  alongside recordings/errors, not alone.
- **Don't invent or assume metrics, scores, or benchmarks.** Only report what was collected, and
  compare to a benchmark only if one is genuinely provided. Treat small samples as directional.

## Qualitative research (from Maze's qualitative methods / thematic analysis articles)

- Qualitative methods (interviews, open-ended responses, secondary research) exist to surface the
  *thoughts, feelings, needs, and pain points* behind behavior — the **why**.
- **Thematic analysis** is the workhorse for large qualitative sets: code observations, group codes
  into themes, and let the review process simplify the volume. Pairs naturally with affinity mapping.
- **Mixed methods** combine qual and quant for both descriptive and statistical insight — e.g.,
  surveys with closed and open questions — without letting either half stand alone.

## How to use these notes

Draw on the *principles* — emergent theming, point-first reporting, metric-plus-context, design-not-
user framing, gaps-are-findings. Do **not** replicate Maze's product-specific report layouts, the
"usability score" as if it were universal, or any structure as a rigid template. These are inputs to
judgment, filtered through this skill's overriding rule: stay grounded in the evidence actually
present.
